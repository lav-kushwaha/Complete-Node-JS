#NOTES :

1. Listen is accepting the req from outside worlds, once we are creating server.
   - listen() is a method on the Express app object that makes the server listen for incoming requests on a specified port.
   - It opens a communication channel (usually on `localhost` or a public IP) and waits for requests from clients.

   Example:
   
   app.listen(3000, () => {
      console.log("Server is listening on port 3000");
   });
   
   This code listens for incoming requests on port `3000` from the outside world.

2. From client side we make request (i.e, localhost:3000) and from server side "listen" is used to accept req from client side and we send response from server side.
   - The client makes requests (e.g., via a browser, Postman, or other tools), and the server listens for these requests using `listen()`.
   - Once a request is received, the server processes it and sends a response back to the client.

   The server uses routes and middleware to handle the incoming request and send an appropriate response.

3. Once we send the response from API, it won't go to the next route handler, and if we don't send any response from API, it will go into an infinite loop.
     - Once you send a response (e.g., using `res.send()`, `res.json()`, etc.), the response cycle is complete**, and the request processing ends. Any subsequent route handlers or middleware will not be executed unless you explicitly call `next()`.
     - If you don't send a response (and don't call `next()`), the request will hang, causing the client to wait indefinitely. This can result in a **"timeout"** or an **infinite loop** from the client's perspective, because the request is never fully completed. 
     - The server will keep waiting for the response.

     To prevent this issue, you should either:
     - Send a response from your route handler (using `res.send()` or similar), or
     - Call `next()` to pass control to the next middleware/route handler.

 4. If we have multiple route handlers and we want to go from one route handler to another, then we have to use `next()`. If we don't use it, it will not go to the next route handler.
     - When you have multiple route handlers or middleware for the same route, you use `next()` to **pass control** to the next handler in the chain.
     - If you don't use `next()` and don't send a response, the request will be stuck in the current handler, and the subsequent handlers will not be executed.
     - If you use `next()`, it ensures that the next handler (or middleware) in the stack is called.

     Example:

     app.use('/user', (req, res, next) => {
         console.log("First handler");
         next();  // Passes control to the next handler
     }, (req, res) => {
         console.log("Second handler");
         res.send("Response");  // Response sent here, no more handlers will execute
     });

### Final Clarified Notes:

1. listen(): This method makes the server start accepting requests on a specified port. It's the entry point for handling client requests.
2. Request and Response: Clients make requests (e.g., `localhost:3000`), and the server handles the requests and sends back a response using routes and handlers.
3. Response and Next Handler: Once a response is sent (via `res.send()`, etc.), the request is completed, and no further route handlers will be executed unless explicitly passed control using `next()`.
4. next()` for Multiple Handlers: When using multiple route handlers or middleware, use `next()` to pass control to the next handler. If you don't call `next()` and don't send a response, the request will be stuck in the current handler.

#Middleware
Middleware: Middleware functions are functions that have access to the request object (req), the response object (res), and the next function in the application's request-response cycle.

Purpose of next():

Passing Control:
The primary purpose of next() is to pass control to the next middleware function in the stack. 
If you don't call next(), the request-response cycle will be halted, and the subsequent middleware functions won't be executed.

Error Handling:
You can also use next() to pass an error object to the error-handling middleware. 
This allows you to gracefully handle errors that occur during the request-response cycle. 

const express = require('express');
const app = express();

app.use((req, res, next) => {
  console.log('First middleware function');
  next(); // Pass control to the next middleware
});

app.use((req, res, next) => {
  console.log('Second middleware function');
  res.send('Hello from the second middleware!');
});

app.listen(3000);
